引擎回答的问题实现
Review这篇写得怎么样、怎么改约 20 项确定性检查 + 段落级可引用性打分 + LLM 评审
EvaluationGEO 到底有没有效果8 平台每日采样，提及率/引用率按站独立计算 + 缺口分析
Recommend下一步该写什么数据驱动的选题生成 + 按站点出内容发布计划
Attribution哪次改动起了作用改动日志 + 时间线对齐（当前只记账，未做归因）
  • 评分底层认知：AI 引用的是段落，不是页面。按标题切块做段落级评估（答案块质量 30% / 自包含 25% / 可读性 20% / 事实密度 15% / 独特性 10%），页面分取最好 5 块的均分，而非给整页一个笼统分。依据是 AI 偏好 134–167 词的自包含段落。
  • SSR 一票否决。AI 爬虫不执行 JS——客户端渲染的漂亮页面在 GEO 视角下约等于空白页，这条直接否决、不参与加权。
  • 国产平台我砍掉了两家。GLM 与混元实测只对时效新闻触发搜索，常青采购题（GEO 主力题型）纯靠记忆回答——采出来是假可见性，比没有数据更危险。宁可少两个平台也不污染数据。
  • 中转站不能想当然。实测中转的 /chat/completions 四模型全部无联网能力，因此采样按各平台原生协议分别打（ChatGPT /v1/responses+web_search、Gemini /v1beta+google_search、Claude /v1/messages+官方搜索工具），评审生成才走 OpenAI 兼容。全部有实测记录。
  • 采样按 RPM 持续派发、不等响应返回，整轮耗时 ≈ 单次最慢延迟而非「次数 × 延迟」；30 条豆包从串行 45 分钟压到 2 分钟。
  • 花钱的地方全有护栏：日预算熔断、平台开关、--dry-run 预估、每轮上限，本地账本按平台分账。
  • 闭环：Agent 写内容 → geo review（<70 分继续改）→ 发布 → geo action 记账 → 每日采样 → report / gaps / plan 拿下一轮指导。
  • 产品化：双层 Web 后台（平台超管 / 租户控制台）、积分账本、先扣费后执行失败退款、pg-boss 定时任务（采样 / 页面观测 / 告警 / 周报）、Docker 部署。
